# Баня у Виктории

Локальный прототип сайта аренды бани в Солигорске на Vue 3, TypeScript, Bootstrap и Vite.

Посетитель знакомится с Викторией, смотрит фотографии бани и спальни, условия, свободные даты и маршрут. Бронь оформляется по телефону; сайт не принимает онлайн-заявки. Количество гостей и часов меняются кнопками «−»/«+» или вводом числа. Для почасовой аренды выбираются дата и время начала. Для посуточной — даты заезда и выезда двумя нажатиями; наведение или фокус показывают предварительный период и стоимость. Количество суток рассчитывается автоматически по разнице дат (13–15 число — двое суток), отдельного счётчика суток нет. Начало сохраняется при переходе между месяцами. Цена рассчитывается как тариф за одного гостя × число гостей × срок аренды. Доступность проверяется на весь период совместно с почасовыми бронями и закрытыми датами; точное время посуточного заезда и выезда согласуется по телефону.

В кабинете Виктория ведёт клиентов и календарь, вручную добавляет и отменяет брони, закрывает даты, меняет тарифы, загружает свой портрет, главное фото бани и фотографии галереи. На каждом дне многодневного проживания отображается бронь. Изменения сразу видны на главной в той же вкладке.

Карточки аренды и быстрые тарифы на главной открывают календарь с выбранным форматом. Для фотографий галереи можно отметить несколько категорий: «Баня», «Спальня» и новые категории из прайса. В кабинете фотографии сгруппированы по категориям, на сайте доступны соответствующие фильтры. Видимых подписей к снимкам нет; описания изображений сохранены для доступности. Увеличенные снимки переключаются свайпом, кнопками и стрелками клавиатуры. После выбора дат можно скопировать сводку для звонка; мобильная кнопка связи использует те же детали. Реальный телефон открывает приложение звонков, а скопированный текст остаётся подсказкой гостю.

Публичная страница оформлена в тёмно-фиолетовой палитре с розовыми акцентами. Световые потоки фона плавно движутся и меняют оттенок при прокрутке между разделами. Анимация работает на CSS без дополнительных библиотек, учитывает уменьшение движения в настройках устройства и приостанавливается в скрытой вкладке. Основной текст формы — 16 px и больше, вспомогательные подписи — от 14 px. Сброс дат оформлен отдельной кнопкой; сводка для звонка — выделяемая текстовая карточка без изменения размера.

## Запуск

Node.js 22.18+ или 24+.

```sh
npm ci
npm run dev
```

Сайт бани открывается на **http://127.0.0.1:5184/**. Порт закреплён: если он занят, запуск остановится с понятной ошибкой и не перейдёт на другой адрес. Для `npm run preview` используется порт 4184.

В PhpStorm выберите конфигурацию запуска **«Баня у Виктории»**: она привязана к `package.json` текущего проекта. После копирования проекта закройте старую вкладку терминала и откройте новую — уже запущенный терминал может оставаться в папке исходного проекта. Если папка терминала неизвестна, запустите явно:

```sh
npm --prefix C:\Users\vovch\Desktop\arendaBanya run dev
```

`npm test` — проверки модели; `npm run build` — TypeScript и production-сборка.

## Ограничения прототипа

Клиенты, брони, тарифы и фотографии остаются демонстрационными: кабинет открывается без авторизации, эти данные находятся в памяти вкладки и исчезают после обновления. Публичный календарь демонстрирует работу общей модели в одной вкладке. Для реальной работы этих разделов ещё нужны серверное хранение, проверка прав и синхронизация.

Отзывы подключаются отдельно по инструкции ниже. Вход в раздел отзывов не защищает демонстрационные разделы клиентов и бронирований — реальные персональные данные пока вводить туда не следует.

Публикация настроена через GitHub Actions: после отправки в main выполняются тесты, сборка и развёртывание на GitHub Pages. В Settings → Pages источником должен быть выбран GitHub Actions. Адрес сайта: https://Vladimir17111991.github.io/arendaBanya/. Относительные пути позволяют открывать сайт как в подпапке GitHub Pages, так и локально.

## Отзывы и модерация

Посетитель отправляет имя, оценку и текст; отзыв получает статус «На проверке». В «Кабинет → Отзывы» Виктория может опубликовать или отклонить его, скрыть опубликованный, вернуть скрытый на сайт, вернуть отклонённый на проверку и добавить/изменить/убрать свой ответ. Исходные текст и оценка посетителя не редактируются. Публичная страница показывает только опубликованные отзывы и ответы к ним.

Без настройки сервера production-сборка показывает пустое состояние и отключает отправку. Она не выдаёт успешную отправку за локальное сохранение и не показывает вымышленные отзывы как настоящие. Для локальной проверки скопируйте `.env.example` в `.env.development.local`: `VITE_REVIEWS_DEMO=true` включает явно обозначенный режим демонстрации с тремя примерами. Оставленный в этой вкладке отзыв появится в её кабинете, но исчезнет после перезагрузки. Флаг игнорируется в production.

### Настройка общей базы Supabase

1. Создайте один проект в аккаунте владельца. Для проверки достаточно Free; код одинаков для Free и Pro. Покупать второй проект для отзывов не требуется.
2. Выполните `supabase/migrations/202610170001_reviews.sql` в SQL Editor нового проекта. Миграция создаёт таблицы, правила доступа и функцию отправки. Повторно выполнять её поверх существующих таблиц не нужно.
3. В Authentication → Users создайте аккаунт Виктории. Пароль вводит владелец в интерфейсе Supabase, он не помещается в код или переписку. Отключите публичную регистрацию новых пользователей, если аккаунт нужен только Виктории.
4. Добавьте UUID созданного пользователя в список модераторов через SQL Editor:

   ```sql
   insert into public.review_moderators(user_id)
   values ('UUID-ПОЛЬЗОВАТЕЛЯ-ВИКТОРИИ');
   ```

5. Возьмите Project URL и **publishable key** (`sb_publishable_…`) в настройках проекта. Задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` в локальном env-файле либо в переменных окружения сборки хостинга. Пересоберите сайт. Эти значения публичные; **secret key, service-role, пароль PostgreSQL и пароль Виктории в `VITE_*` помещать нельзя**.
6. Откройте «Кабинет → Отзывы», войдите почтой и паролем аккаунта Виктории. Из другого браузера отправьте тестовый отзыв, убедитесь, что он скрыт до публикации, виден после неё и исчезает после скрытия. Удалите тестовые записи через SQL Editor владельца перед запуском.

Роли обеспечиваются PostgreSQL RLS и правами столбцов. Обычный посетитель не читает очередь и не меняет статус/ответ. Сам факт входа в Supabase не даёт прав модерации: нужен UUID в `review_moderators`. Повтор отправки с тем же ID не создаёт дубликат. Одновременные изменения защищены проверкой `updated_at`. Вход сохраняется в этом браузере после обновления и возвращения «На сайт». Кнопка «Выйти из отзывов» завершает сессию; повторный вход также потребуется после её отзыва или очистки данных браузера. После выхода закрытый список очищается, включая запоздавшие ответы сети. Ответ подписывается «Ответ администрации».

Для GitHub Pages задайте в Settings → Secrets and variables → Actions → Variables значения `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`: workflow передаёт их сборке. Это публичные настройки клиента, не серверные секреты.

Публичный список ограничен последними 100 опубликованными отзывами. В кабинете отзывы разделены на страницы по 10: переключение расположено сверху и снизу списка. Обновление и модерация сохраняют текущую страницу, опустевшая последняя страница автоматически переключается на предыдущую; смена статуса начинает список с первой страницы. Премодерация предотвращает публикацию нежелательных текстов, но сама по себе не ограничивает массовую отправку запросов: перед публичным приёмом следует настроить защиту от ботов/ограничение частоты на сервере. В эту миграцию не входят клиенты, брони и загрузка фотографий.

GitHub Pages остаётся площадкой просмотра прототипа. Перед запуском защищённого кабинета на рабочем сайте выберите подходящий хостинг с учётом [ограничений GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits). Подключение Supabase не требует переноса исходников с GitHub.

### Проверка прав базы

`supabase/tests/reviews.sql` проверяет миграцию в **пустой одноразовой PostgreSQL**, включая гостевую отправку, запрет самостоятельной публикации/выдачи роли, недоступность очереди обычному аккаунту, публикацию, ответ и скрытие. Файл создаёт тестовые роли и схему `auth`, поэтому **не запускается в рабочем Supabase**. В пустой локальной базе: `psql -v ON_ERROR_STOP=1 -f supabase/tests/reviews.sql`.
